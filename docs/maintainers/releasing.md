# 发布流程（维护者）

本文面向维护发布版本的开发者。普通用户从 Releases 下载安装包，不需要配置发布环境或签名密钥。

版本号和仓库地址统一在 `release.config.json` 管理。构建自动生成 C# 版本常量、程序集版本和安装清单，插件读取同一版本配置。

## 常规验证

提交和 PR 运行脚本测试、密钥备份测试、开发构建和管理器测试。开发构建使用一次性测试密钥，不接触发布私钥，不进入正式更新源。

## 正式版本

1. 更新配置中的版本及版本说明，完成测试和代码审阅。
2. 创建指向该提交的 `v版本号` 标签，由发布工作流构建签名安装包，并创建 GitHub 预发布版本。
3. 从该预发布下载原始文件，验证签名、真实客户端暂停、旧版升级、设置保留和回退。模拟测试不能代替真实验收。
4. 验收通过后将该 Release 转为稳定版并设为最新版本。同一发布包不重新构建或覆盖；其签名 `stable.json` 开始通过稳定更新地址对外提供。

本地正式构建使用原有 DPAPI 私钥。自动发布需要在 GitHub `release` 环境配置 `LEIGOD_SIGNING_KEY_XML`，仅受信任标签上的发布任务可用。不要在 Issue、聊天、命令参数或工作流日志中传递密钥。

配置好 GitHub CLI 登录和 `release` 环境后，可以使用以下命令通过标准输入配置密钥，不需要复制到网页：

```powershell
pwsh -File scripts/configure-publisher.ps1 -BackupReceipt '已验证备份.p8.json'
```

该命令先核对备份回执、加密文件摘要与公钥身份，不自动创建或替换发布密钥。

签名发布前必须完成加密备份和恢复验签。备份不能只放在这台电脑，也不能只依赖 GitHub Secrets。参见 [发布密钥管理](signing.md)。

当前更新协议固定信任发布公钥，不能在私钥丢失后承诺旧客户端自动迁移到新公钥。
